
0.5.91 generated build-module manifests
- Common/BuildModuleManifests/*.buildmodule is now the source of truth for common SDK build/archive modules.
- Targets/UEFI/X64/BuildModuleManifests/*.buildmodule is now the source of truth for UEFI x64 target build/archive modules.
- Targets/UEFI/X64/OrynBuild/BuildPlanModules.c now loads build modules from manifest files instead of hard-coded ADD tables.
- Common/Kernel/ModuleManifests/*.module remains the source of truth for kernel runtime module IDs, items, and prerequisites; generated C is rebuild output, not hand-owned manifest data.


0.5.93: fixed OrynLibC signed integer conversion proof failure in strtoll/strtol.

0.5.94 OrynLibC split-source layout:
- Most public LibC functions now compile from individual source files under Common/OrynLibC/Source.
- Shared allocator and rand state live in small private state units.
- Private helpers remain file-local where they support one public entry point.

0.5.95 archive rebuild rule:
- Module archives are deleted before llvm-ar recreates them.
- This prevents stale archive members from removed/split source files causing duplicate symbols after ChangedFiles updates.
OrynLibC function-unit manifests
- Common/OrynLibC/FunctionManifests/<category>/<unit>.libcunit is the per-function/per-unit inventory contract.
- Common/OrynLibC/Source remains the implementation authority.
- The native build validates every LibC .c source against these manifests before archive resolution.
- The validation report is written to Build/Plan/LibCFunctionUnitManifestReport.txt.



0.5.97 LibC host conformance layout:
- Common/OrynLibC/Tests/Host/TestOrynLibCHostConformance.c contains external host-side behavioral tests.
- Common/Scripts/RunLibCHostConformance.sh compiles and runs the host conformance executable and writes reports.
- Common/OrynBuild/LibCConformanceCommand.c exposes the test as oryn libc-test.
- Common/Reports/LibCConformance/ is generated output and not package source.
0.5.99 BootProof category ownership layout:
- Targets/UEFI/X64/KernelSupport/Source/Runtime/KernelRuntimeBootSequence.c remains runtime-only and contains no category proof decisions.
- KernelBootProofOrchestrator.c owns boot-proof phase dispatch, panic handoff, running-state transition, and halt proof dispatch.
- KernelBootProofCategories.c owns boot proof category ordering and optional-module category checks.
- KernelDiagnosticsBootProofs.c owns reusable proof helper output only, not boot sequence orchestration.


0.5.99 layout update:
- Targets/UEFI/X64/KernelSupport/Include/KernelDiagnosticsLogger.h owns proof-time serial detail logging API.
- Targets/UEFI/X64/KernelSupport/Source/Diagnostics/KernelDiagnosticsLogger.c owns the only Diagnostics/BootProof bridge to KernelIo serial detail output.
- Targets/UEFI/X64/KernelSupport/Include/KernelInitGraph.h defines ordered kernel init stages and dependencies.
- Targets/UEFI/X64/KernelSupport/Source/Diagnostics/Proofs/KernelInitGraph.c contains the KernelInit graph data and validation.

0.5.101 Kernel heap layout:
- Common/Kernel/Include/KernelHeap.h exposes kmalloc, kfree, krealloc, kcalloc, heap stats, leak counters, slab cache stats, and guard-page proof APIs.
- Common/Kernel/Source/Memory/KernelHeap.c owns the physical-page backed kernel heap, fixed-size slab caches, critical allocation guard accounting, and self-test.
- Common/Kernel/ModuleManifests/20-Heap.module is the generated manifest source for the Heap module.
- Common/Kernel/ModuleManifests/21-VirtualMemory.module now depends on Heap, making Heap the explicit stage between PhysicalMemory and VirtualMemory.
- Targets/UEFI/X64/KernelSupport/Source/Diagnostics/Proofs/KernelDiagnosticsMemoryProofs.c owns heap init/start proof as part of memory proof flow.
- Targets/UEFI/X64/KernelSupport/Source/Memory/KernelVirtualMemory.c exposes OrynVirtualMemoryUnmapGuardPage for stack and critical-heap guard-page support.

0.5.102 virtual-memory policy layout:
- Targets/UEFI/X64/KernelSupport/Include/KernelPageFaultPolicy.h declares fatal/non-fatal page-fault policy state and actions.
- Targets/UEFI/X64/KernelSupport/Source/Memory/KernelPageFaultPolicy.c owns page-fault policy classification and proof coverage.
- Targets/UEFI/X64/KernelSupport/Include/KernelVirtualMemory.h now exposes address-space objects, user/kernel split constants, and map/unmap/protect APIs.
- Targets/UEFI/X64/KernelSupport/Source/Memory/KernelVirtualMemoryApi.c owns process address-space creation plus virtual map/unmap/protect operations.
- KernelInterrupts dispatches page faults through KernelPageFaultPolicy before panic escalation.
