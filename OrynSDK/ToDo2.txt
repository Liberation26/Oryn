OrynWsl ToDo2 - Linux-like Full Kernel Roadmap
Version: 0.5.61
Purpose: Define the work needed to grow OrynWsl from the current boot-proven kernel into a full kernel that behaves like a small Linux-class operating system.

Meaning of "Linux-like":
Oryn is not meant to copy Linux source code or become a Linux distribution.
Oryn is meant to provide the same kind of kernel capability that makes Linux useful:
- protected processes;
- pre-emptive multitasking;
- user/kernel isolation;
- a virtual filesystem;
- block devices and filesystems;
- external userland programs;
- a network stack;
- drivers bound through a device model;
- stable kernel/user ABI;
- diagnostics, logging, panic, crash, and recovery paths;
- repeatable builds and automated boot tests.

Status tags:
[ OK ] Implemented enough for the current release target.
[WARN] Present but partial, smoke-test only, or not production-safe.
[TOBE] Required future work.
[FAIL] Known blocker or contradiction.

Hard project rules:
[ OK ] Native C SDK only. No .NET runtime inside the kernel path.
[ OK ] UEFI is a loader target only. The kernel must not call UEFI after handoff.
[ OK ] Kernel receives plain OrynBootInfo and then owns the machine.
[ OK ] Screen output rule: framebuffer status screen shows only OK, WARN, or FAIL category lines.
[ OK ] Detailed proof output belongs on serial/debug output and boot reports.
[ OK ] Exactly three kernel syscall concepts: Get, Set, Event.
[ OK ] Shell commands must become external programs, not hardcoded internal commands.
[ OK ] No .inc files in delivered source.
[ OK ] Source code must follow the Single Responsibility Principle.
[ OK ] Keep source files under 500 lines. Split by function or responsibility.
[ OK ] Incremental C-to-object compilation must remain the default.

Recommended implementation order:
1. Clean KernelMain and move proof/report logic into modules.
2. Finish kernel heap and virtual-memory APIs.
3. Finish interrupt queues, deferred work, and monotonic clock.
4. Build scheduler and kernel threads.
5. Enter user mode with one test process.
6. Build VFS and file descriptors.
7. Build block device + FAT32 read path.
8. Load external shell from /System/Commands or /System/Shell.
9. Convert commands into external programs.
10. Add process isolation, exec, wait, and stdout/stderr routing.
11. Add storage write support.
12. Add networking.
13. Add security, permissions, and crash recovery.
14. Add POSIX/Linux compatibility wrappers on top of Get/Set/Event.

[TOBE] Runs multiple isolated user processes.
[TOBE] Schedules threads pre-emptively.
[TOBE] Loads external user programs from the filesystem.
[TOBE] Provides a VFS and file descriptors.
[TOBE] Reads and writes persistent files safely.
[TOBE] Supports at least one real block storage path.
[TOBE] Supports at least one network device and basic TCP/IP.
[TOBE] Provides a shell as a userland program.
[TOBE] Keeps internal kernel ABI as Get, Set, Event.
[TOBE] Provides POSIX/Linux-like wrappers above the Oryn ABI.
[TOBE] Has clear OK/WARN/FAIL screen status and detailed serial diagnostics.
[TOBE] Has automated QEMU regression tests for every major subsystem.
