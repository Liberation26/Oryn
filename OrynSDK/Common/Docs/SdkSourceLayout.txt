Oryn SDK source layout
======================

The SDK is now split at the SDK root into only two implementation trees:

  OrynSDK/Common
  OrynSDK/Targets/UEFI/X64

Only thin root launchers remain beside those trees:

  OrynSDK/Oryn.sh
  OrynSDK/oryn
  OrynSDK/update
  OrynSDK/update.sh
  OrynSDK/VERSION

Common/shared modules
---------------------

  Common/Bin        Native SDK tool output, including the bootstrapped oryn executable.
  Common/Docs       SDK documentation that is not target-specific.
  Common/Handoff    Target-neutral BootInfo ABI headers shared by boot targets and kernels.
  Common/OrynBuild  Target-neutral native Oryn build-tool source only.
  Common/OrynLibC   Early freestanding C support shared by kernel targets.
  Common/Scripts    SDK operational scripts.

Target-specific modules
-----------------------

  Targets/UEFI/X64/Boot/Include    UEFI x64 default BootInfo selection and boot-target policy headers.
  Targets/UEFI/X64/Kernel.ld       UEFI x64 kernel linker script.
  Targets/UEFI/X64/KernelSupport   UEFI x64 kernel-side CPU, interrupt, timer, serial, and virtual-memory support.
  Targets/UEFI/X64/Loader/Include  UEFI x64 loader headers.
  Targets/UEFI/X64/Loader/Source   UEFI x64 loader source, including BootX64Entry.c.
  Targets/UEFI/X64/OrynBuild       UEFI x64 build/image/run/BootInfo questionnaire integration for the native oryn tool.

Rules
-----

  Common must not depend on a concrete target, firmware, boot style, GOP, OVMF, BOOTX64.EFI, or QEMU UEFI launch details.
  UEFI, BIOS, and future boot styles must keep their boot-specific policy and implementation under Targets/<BootStyle>/<Architecture>.
  Targets may depend on Common.
  New architectures and boot styles should be added under Targets/<BootStyle>/<Architecture>.

0.5.5 correction
----------------

  The previous 0.5.4 layout still had SDK peer directories such as Source, Bin, Docs, and Scripts at the SDK root.
  0.5.5 removes that ambiguity: SDK implementation directories are now Common or Targets/UEFI/X64.
  The old Source, Bin, Docs, and Scripts paths are removed automatically on the next Oryn.sh run or update.

0.5.17 kernel support move
--------------------------

  Shared kernel support was moved out of OrynProjects/Kernel-5 and into the SDK.
  Kernel-5 now owns only its project entry point, project manifest, BootInfo selection variants, and project assets.
  Target-neutral support lives in Common/Kernel.
  UEFI x64-specific support lives in Targets/UEFI/X64/KernelSupport.
  The Oryn build stage compiles SDK common kernel source, SDK target kernel source, and project source into one linked OS-named ELF image, for example Build/Kernel-5.elf or Build/<OSName>.elf.


0.5.18 handoff checksum ABI
----------------------------

  OrynBootInfo ABI v7 keeps the checksum and boot-configuration contracts in Common/Handoff/Include/OrynBootInfo.h.
  Loader-side sealing happens in Targets/UEFI/X64/Loader/Source/BootX64Handoff.c.
  Kernel-side verification happens in Common/Kernel/Source/BootInfo/KernelBootInfoValidate.c.
  Project KernelMain validates BootInfo before initializing framebuffer/font console state.


Higher-half/chosen kernel layout
--------------------------------
The UEFI x64 target owns Kernel.ld and loader-side paging setup. Common BootInfo carries the plain physical and virtual kernel layout fields, while target code decides how to map and enter the kernel.


0.5.25 boot configuration ownership
-----------------------------------
The user project owns the saved boot configuration values in Project.oryn:

  [BootConfiguration]
  CommandLine=...

The SDK owns the ABI and transport:

  Common/Handoff/Include/OrynBootInfo.h defines OrynBootConfigurationBlock.
  Targets/UEFI/X64/OrynBuild/Image.c generates OrynBootTarget.h.
  Targets/UEFI/X64/Loader/Source/BootX64.c fills the block before handoff.
  Common/Kernel/Source/BootInfo validates and prints the block.

0.5.26 IDT ownership
  x86_64 IDT code is SDK target kernel support under Targets/UEFI/X64/KernelSupport, not project-owned kernel code.

0.5.28 GDT ownership/runtime proof
- KernelGdt.h and KernelGdt.c live under Targets/UEFI/X64/KernelSupport.
- GDT/TSS setup is target-owned CPU support, not project-owned kernel code.
- Kernel-5 only calls the SDK target support from KernelMain.

0.5.29 PIC/APIC2/HPET ownership
--------------------------------
The early x64 interrupt/timer foundation is target-owned SDK code, not project-owned kernel code:

  Targets/UEFI/X64/KernelSupport/Include/KernelPortIo.h
  Targets/UEFI/X64/KernelSupport/Include/KernelCpu.h
  Targets/UEFI/X64/KernelSupport/Include/KernelMsr.h
  Targets/UEFI/X64/KernelSupport/Include/KernelPic.h
  Targets/UEFI/X64/KernelSupport/Include/KernelApic.h
  Targets/UEFI/X64/KernelSupport/Include/KernelHpet.h
  Targets/UEFI/X64/KernelSupport/Source/IO/KernelPortIo.c
  Targets/UEFI/X64/KernelSupport/Source/CPU/KernelCpu.c
  Targets/UEFI/X64/KernelSupport/Source/CPU/KernelMsr.c
  Targets/UEFI/X64/KernelSupport/Source/Interrupts/KernelPic.c
  Targets/UEFI/X64/KernelSupport/Source/Interrupts/KernelApic.c
  Targets/UEFI/X64/KernelSupport/Source/Timers/KernelHpet.c

Kernel-5 only invokes this support from KernelMain. Common remains target-neutral.


0.5.30 Interrupt dispatcher ownership
-------------------------------------
The interrupt dispatcher is target-owned UEFI x64 kernel support, not common code and not project-owned code:

  Targets/UEFI/X64/KernelSupport/Include/KernelInterrupts.h
  Targets/UEFI/X64/KernelSupport/Source/Interrupts/KernelInterrupts.c

The dispatcher is the bridge above the IDT stubs and below the controller-specific EOI paths. PIC IRQ0 is proven first, then the local APIC/APIC2 timer interrupt is proven.

0.5.31 SysCall ownership
------------------------
The internal syscall ABI is common kernel support because Get/Set/Event message packets are target-neutral:

  Common/Kernel/Include/SysCall.h
  Common/Kernel/Include/LinuxSysCall.h
  Common/Kernel/Include/MSSysCall.h
  Common/Kernel/Source/SysCalls/SysCall.c
  Common/Kernel/Source/SysCalls/LinuxSysCall.c
  Common/Kernel/Source/SysCalls/MSSysCall.c

The UEFI x64 target owns the interrupt-vector receive bridge only:

  Targets/UEFI/X64/KernelSupport/Include/KernelSysCallInterrupts.h
  Targets/UEFI/X64/KernelSupport/Source/Interrupts/KernelSysCallInterrupts.c

IDT vectors 0x80 and 0x81 are marked callable from user privilege later, while the current Kernel-5 proof invokes them from kernel mode to validate translation and debug logging before a process/userland layer exists.

0.5.32 SysCall count ownership
-------------------------------
Common/Kernel/Include/LinuxSysCall.h owns:

  ORYN_LINUX_SYSCALL_LISTED_COUNT = 11
  ORYN_LINUX_SYSCALL_TRANSLATED_COUNT = 4

Common/Kernel/Include/MSSysCall.h owns:

  ORYN_MS_SYSCALL_LISTED_COUNT = 6
  ORYN_MS_SYSCALL_TRANSLATED_COUNT = 4

These constants are intentionally kept with the platform compatibility headers so BootReport and kernel diagnostics can prove what each header currently covers.




0.5.34 Diagnostic colour and PCI English ownership
--------------------------------------------------
The common kernel console owns framebuffer/VGA status colours through KernelConsole.h and KernelConsole.c. KernelIo.c owns line-prefix detection and fans status colours out to serial COM1, QEMU debugcon port 0xE9, and the kernel screen. The UEFI loader BootX64Io.c mirrors serial/debug ANSI colour before kernel handoff.

PCI device English labels remain target-owned with the UEFI x64 PCI support because the decoded inventory is produced by the target PCI scanner:

  Targets/UEFI/X64/KernelSupport/Include/KernelPci.h
  Targets/UEFI/X64/KernelSupport/Source/PCI/KernelPci.c

KernelPci now exposes helper names for vendor, class, subclass, header type, and interrupt pin output.

0.5.33 PCI Discovery ownership
------------------------------
PCI discovery is target-owned UEFI x64 kernel support because the current implementation uses x86 PCI config mechanism #1 and target boot ACPI mappings:

  Targets/UEFI/X64/KernelSupport/Include/KernelPci.h
  Targets/UEFI/X64/KernelSupport/Source/PCI/KernelPci.c

KernelPci validates the BootInfo RSDP, discovers ACPI MCFG/PCIe ECAM metadata, then scans PCI config space and exposes a recorded device list to Kernel-5 diagnostics. Common remains target-neutral; later common driver registries can consume this target-produced device inventory.


0.5.37 SMP ownership
--------------------
SMP/multi-core processing is target-owned UEFI x64 kernel support because it depends on x86_64 local APIC IDs, ACPI MADT CPU entries, and the real-mode AP startup trampoline:

  Targets/UEFI/X64/KernelSupport/Include/KernelSmp.h
  Targets/UEFI/X64/KernelSupport/Source/SMP/KernelSmp.c
  Targets/UEFI/X64/KernelSupport/Source/SMP/KernelSmpTrampoline.c

KernelSmp discovers CPUs from the BootInfo RSDP/MADT path, prepares the low-memory AP trampoline, starts APs with local APIC INIT/SIPI, and reports AP startup to Kernel-5 diagnostics. The QEMU run stage now includes -smp 4 and BootReport checks the SMP proof markers.

0.5.37 boot-proof ordering
--------------------------
KernelMain now prints early entry/BootInfo proof before descriptor, interrupt, PCI, memory, and SMP proofs.
KernelInterrupts provides separate PIC and APIC runtime proof printing so PIC-upwards failures are visible at the correct stage.
KernelSmp is still target-owned and now starts APs after the kernel-owned virtual memory PML4 is active.
